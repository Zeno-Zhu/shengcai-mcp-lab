# 报告模板与价值判断

## 全局案例与来源规则

除朋友圈卡外，所有阅读类交付都要让读者回到具体材料。适用于日报、周报、方向研究、单篇拆解、作者动态、项目课题、航海和深海圈学习笔记。

- 文章、案例或圈友经验进入主推荐时，写清圈友名、帖子标题、时间和可打开的原帖链接。
- 叙述“怎么做”时保留起点、关键动作、判断节点、结果或反馈、代价或限制。动作数量由原文决定，不能为了简短删掉影响理解的步骤。
- 作者有清楚的操作判断、风险提醒或取舍时，保留完成当前判断所需的原文。深读资料按 `track-research.md` 保存 1—5 个带上下文片段；速读报告只保留一条短引文，并紧接说明它对当前主题的意义。
- 事实、作者观点、报告判断三者分开写。材料没有给出的成本、结果或因果，一律标为未知。
- 日报和周报可把同类帖子聚成主题，但每个主题至少保留一张可复述案例卡，不把多个圈友的动作揉成无出处的“市场趋势”。

朋友圈卡是唯一例外。它只输出整理后的内容、判断和个人阅读体会，不展示圈友名、帖子标题、原帖链接、来源脚注或引用标记。卡片的事实仍需来自母稿，不能为了去来源而编造细节。

## 信息密度与分层交付

报告的目标不是把原文缩到最短，而是让读者用更少的阅读阻力，拿到足够作判断的信息。先保留信息单元，再决定呈现形式。

一个信息单元至少包含其中两项，主推荐必须有前三项：

| 信息单元 | 要保留的内容 |
| --- | --- |
| 事实 | 作者做了什么，给出什么数据、案例、工具、动作或结果？ |
| 取舍 | 作者在什么选择里放弃了什么，保留了什么？ |
| 推理 | 从事实到结论，中间依赖了什么机制或前提？ |
| 条件 | 什么人、资源、阶段或约束下才成立？ |
| 未知 | 原帖没有证明什么，哪些只是作者经验或观点？ |

删除重复修辞、泛化鼓励和换词复述。不得删除作者特有的做法、取舍、数据、反例和限制，再用泛泛的“启发”替代。

### 三层交付

| 层级 | 读者用途 | 信息保留要求 | 推荐形式 |
| --- | --- | --- | --- |
| 深读母稿 | 归档、研究、继续提问 | 每篇至少保留 4 个独特信息单元，附原帖链接、证据性质和未知项 | Markdown / HTML 长文 |
| 速读简报 | 3–7 分钟理解全貌 | 每篇保留事实、取舍、推理、边界各 1 项；用表格、关系图、时间线代替连接性废话 | 网页简报 |
| 分享卡 | 让人愿意点开和带走一个判断 | 一张只讲一个主题或一篇文章，保留 1 个事实、1 个判断、1 个边界；多篇文章必须拆卡 | 3–5 张卡片 |

“摘要”只能属于速读层，不能取代深读母稿。朋友圈卡是阅读入口，不承担完整报告。用户说“朋友圈卡”且材料超过一个主题时，默认交付卡组和可打开的母稿，不把全部内容塞进一张图。

### 原文保真与人类阅读

深读资料不能只给“问题、方法、结果”三个抽象句子。至少恢复作者从起点到结果的关键过程，并穿插能支持理解的原文片段。摘录前后要说明它正在证明什么，不能把引文集中堆在文末。

原文片段优先保留作者特有的判断、步骤、数据、返工和限制。每段通常 80—300 个汉字，保留最小充分上下文；省略使用 `[…]`。公开文章和分享卡使用更短的引文，避免让摘录替代原帖。

资料写完后，让一个不了解该行业的人试着回答：作者原来怎么做，后来为什么改，具体改了哪里，结果和代价是什么。回答不出来时，说明压缩过度，需要回到原文补材料。

### 单篇信息保真卡

对值得读的帖子，按下面顺序组织内容：

1. 这篇解决的具体问题。
2. 作者实际做了什么，保留 2–4 个独特事实或做法。
3. 作者为什么这样取舍，连出推理链。
4. 哪些条件具备时可以借，哪些地方只是个人经验。
5. 读者带着什么问题去读原文。

写完做一次反向检查。把作者名、标题和领域藏起来后，这段文字若能套进任意一篇 AI 帖子，说明内容被抽象过头，必须回到原帖补细节。

### 决策报告的圈友案例卡

用户要在多个方向间做取舍时，不能只写“有案例支持”。每个主方向至少给出一张可复述的圈友案例卡。

| 字段 | 要求 |
| --- | --- |
| 谁 | 圈友名、原帖标题、发表时间与原帖链接。 |
| 起点 | 他当时有什么资源、卡点或约束。 |
| 怎么做 | 按时间保留 2–4 个关键动作，不能只写“持续做内容”或“做了服务”。 |
| 结果 | 播放、收入、成交、失败、时间成本或客户反馈。原帖没给结果时明确写出。 |
| 作者原话 | 选一段能保留完整意思的操作判断、风险提醒或取舍。速读卡优先控制在 15—80 个汉字，深读资料按 `track-research.md` 保留上下文。 |
| 对本决策的意义 | 这张案例支持什么，不支持什么，迁移前需要哪些条件。 |

案例卡至少包含一个结果和一个代价。成功案例不等于路径已被证明，失败、政策变化和前提缺失也必须保留。引用必须短、可回溯到原帖，优先引用作者对动作、约束和判断的原话。

## 先做价值判断

每条推荐内容先过五个问题。只满足其中一两个时，放在“选读”或“观察”，不占主推荐。

| 维度 | 要回答的问题 |
| --- | --- |
| 事实 | 作者或平台实际做了什么，时间、数据、结果是什么？ |
| 证据 | 数据来自原帖、官方变化、多个案例，还是作者单方描述？ |
| 机制 | 为什么可能有效，靠需求、分发、产品、交付、留存还是自动化？ |
| 适用 | 哪类用户、能力和阶段可以借，迁移距离多远？ |
| 边界 | 缺什么条件、存什么风险、哪些结论还不能下？ |

推荐项写成“事实 + 我读到的判断 + 适用边界”。不只列标题、热度和泛泛启发。

## 场景路由

### 昨日风向标

目标是看变化，默认 3–5 条。

每条写：发生了什么、变化落在哪个环节、证据强弱、和方向卡的关系、应归为动作/课题/观察。拓展信号单列，解释为什么值得跨界读以及为什么暂不行动。

### 近期期精华帖

目标是安排阅读顺序。“最近”默认取过去 7 天，且使用精华分区或 `isDigested=true` 过滤。默认 3 篇主读加 2 篇选读；结果不足时如实交付实际数量，并说明检索时间窗。用户明确要主题簇或周报时才混入风向标和日常帖，且必须分区呈现。

每篇写：作者解决的具体问题、做法和结果、可借的一个变量、适用人群、当前不建议照搬的地方、阅读时要带着的问题。读完后给一个“本周只验证什么”的收口，不能把每篇都变成项目。

### 单篇拆解

目标是判断一篇文章值不值得花时间。

按“事实与结果、做法、为什么有效、成本与限制、可迁移部分、我的结论”展开。材料不足时标注“原帖未提供”，不补写商业故事。

### 作者最新动态

目标是看一个人最近在推进什么、哪些判断重复出现、哪些变化可能影响后续动作。

按时间列最近内容，再归纳为“新动作、重复判断、还缺的证据、对我有用的启发”。图片型或链接型内容没有正文时，只写可见信息，不硬猜思想。

### 航海、深海圈与课程

目标是把学习资料变成进度。

写清项目目标、当前阶段、关键章节或任务、已完成证据、常见卡点、下一项最小作业。课程目录不等于学习建议，必须解释为什么此时先学它。

### 圈友与链接准备

目标是找到可以推进事情的人。

写公开作品或讨论线索、相交点、对方可能关心的事、我可以先给出的价值、一个窄问题。不得把搜索到的人包装成“人脉资源”。

## 公开卡模板

单条强信号用 1 张；多篇阅读使用 3–5 张，默认三张。

### 卡 1 这次看什么

写时间、主题和一个平实判断。例子：“这周留了三篇 AI 阅读笔记。它们分别讲视频怎么跑出反馈、内容怎么拆进流程、Agent 怎样从聊天走到干活。”

### 卡 2 事实与判断

每项限制在三行。

1. 具体事实或数据。
2. 我从中读到的判断。
3. 适用边界或提醒。

### 卡 3 读完留下什么

写 2–3 个值得继续想的问题、阅读线索或可复用的检查项。公开卡不分配读者任务，不写私人项目计划。

## 私人报告模板

私人报告可连接方向卡，分成“和我相关、值得扩展、暂缓”三栏。每个行动项要写目标、成本、截止时间和可见结果；公开卡不带这些内容。

## 语言规则

- 先写事实，再写判断，最后写边界。
- 用短句、常用词和具体动词。数据写明来源和性质。
- 少用“核心、底层、闭环、赋能、抓手、认知”等抽象词。
- 不用“不是……而是……”“你当前最该补”“先说结论”等句式。
- 没有用户口语样本时，采用平实、温和的第一人称分享口吻。
