# 手绘知识卡视觉规范

生财 MCP Skill 的公开配图只使用这一套风格。目标是让研究、流程和方法看起来亲切、清楚、有手作感，避免企业汇报图和通用 SaaS 模板感。

## 视觉语言

- **背景**：暖米白纸张，保留轻微纸纹。
- **线条**：黑色马克笔或钢笔手绘线，允许轻微不规则，不追求机械对齐。
- **标题**：大号黑色手写中文，字形有力量但容易辨认。
- **色块**：低饱和桃色、天蓝、薄荷绿、淡黄、淡紫，承担分区与语义，不使用大面积渐变。
- **角色与物件**：友好的小机器人、普通工作者、文件夹、文档、清单、齿轮、插头、电脑、放大镜、权限锁、对勾和箭头。
- **关系线**：粗黑箭头表示主流程，彩色虚线表示反馈、回环和补充关系。
- **气质**：像圈友认真画的一张知识笔记，信息充足，语气温和，不做幼儿卡通或商业海报。

## 构图

### 流程图

用 3—8 个手绘卡片承载步骤。步骤少时横向排，步骤多时使用两行回转路径。判断、返工和反馈必须用箭头画清楚。

### 对比图

每个方案占一个彩色分区，标题、适用条件和小图标一一对应。多个工具属于并列选择时，不画成固定升级阶梯。

### 金句图

金句占画面约三分之一，同时配一条事实或一段小流程解释它为什么重要。写明作者；正文附近保留完整原帖链接与研究者理解。

### 总结图

只总结正文已经证明的 3—5 个判断。每个判断配一个业务物件或动作，不用抽象口号填满画面。

有用户提供的参考图时，把它标记为“风格参考”，不复制其中的主题、文字、构图和品牌元素。

## 文字准确性

图里的关键文字来自母稿，生成前单独列出。生成后逐字检查：

- 标题；
- 人名与署名；
- 工具英文名；
- 数字、时间和单位；
- 步骤顺序；
- 判断与返工箭头。

图像模型第一次出现错误时，只针对错误内容重做该图。第二次仍错，保留插画和构图，改用 HTML、SVG 或其他确定性文字层。不能把错字图插入文章。

## 信息密度

- 一张图只解决一个阅读问题。
- 1 个判断适合金句卡；2—4 个要点适合均衡分区；5—8 个步骤适合流程图。
- 主体覆盖安全画布约 78% 以上，不能用大块空白掩盖内容不足。
- 文章图里的正文保持短，完整解释放回 Markdown。
- 同一篇文章的图片共用背景、线条、色块和角色语言，不能每张换风格。

## 来源边界

原帖截图和作者图片原样保留，不套手绘风格，不修改数据。研究者制作的新图可以使用手绘知识卡，但必须在正文附近说明：

- 原文明确给出的事实；
- 作者自己的判断；
- 我们根据多篇资料整理的流程或总结。

三类信息不能在图中混成同一个作者观点。
