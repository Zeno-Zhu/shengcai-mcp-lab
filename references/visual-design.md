# 卡片视觉设计路由

## 三层组合

```text
研究母稿
  ├─ 信息结构与文字  HTML/CSS 负责
  ├─ 版式和插画      Baoyu 负责
  └─ 最终合成         HTML 将准确文字叠在视觉层上
```

关键文字始终由 HTML 渲染。Baoyu 图层不承担长中文、数字、日期、原帖标题、链接或结论。

## 按场景选结构

| 场景 | 视觉目标 | 推荐 Baoyu 路线 | 卡组形态 |
| --- | --- | --- | --- |
| 昨日风向标 | 看清变化与优先级 | `baoyu-infographic` 的 `bento-grid` 或 `radar` 式结构；数据多时用 `technical-schematic` | 封面、信号卡、判断卡 |
| 精华阅读清单 | 看清每篇值不值得读 | `baoyu-xhs-images` 的 `notion + list/dense`，搭配书签、便签、资料夹等原创元素 | 范围卡、案例卡、问题卡 |
| 作者动态 | 看清近期动作与重复判断 | `baoyu-infographic` 的 `linear-progression` 或 `winding-roadmap`，不用真人肖像替代材料 | 时间线、判断卡、阅读体会 |
| 单篇文章拆解 | 看清做法和约束 | `baoyu-infographic` 的 `structural-breakdown`、`bridge` 或 `funnel` | 事实卡、机制卡、边界卡 |
| 航海与课程 | 看清学习进度和下一关 | `baoyu-infographic` 的 `linear-progression + ikea-manual` | 地图卡、任务卡、复盘卡 |
| 圈友链接 | 看清相交点与交流入口 | `baoyu-xhs-images` 的 `notion + mindmap`，不生成真实人物肖像 | 共同点、作品线索、提问卡 |

## 视觉方案

每次首次做视觉卡时，展示 2–3 个方案。建议默认给出以下选项。

| 方案 | 气质 | 适合内容 |
| --- | --- | --- |
| 编辑部研究卡 | 暖白纸张、墨绿、细线、资料标签 | 风向标、精华阅读、作者动态 |
| 知识笔记卡 | `notion + dense`，手绘图标、资料夹、便签 | 教程、阅读清单、方法拆解 |
| 温和故事卡 | `warm + balanced`，柔和色块、少量场景插画 | 人物经历、服务案例、情绪主题 |

## 画面规则

- 一张卡只放一个主视觉。视觉要帮助读者理解“变化、路径、比较或场景”。
- 使用原创抽象插画、几何结构、物件或场景。没有用户提供的授权素材时，不生成现实人物肖像或冒充作者照片。
- 视觉占画面 25%–45%，文字区保持足够对比度和留白。
- 生成提示词只描述画面、构图、色彩和无文字留白区。关键文字在 HTML 中覆盖。
- 同一组卡共用配色、线条、纹理和图形语言。每张卡可改变结构，不能每张换一种风格。

## 内容密度决定版式

同一张背景不能套给所有页面。先数当前卡片需要保留的独特信息单元，再选版式。空白只在帮助聚焦、停顿或承载主视觉时成立；没有阅读功能的大块空区属于版式失配。

| 当前卡片的信息单元 | 版式 | 画面安排 |
| --- | --- | --- |
| 1 个完整判断，附 1 个事实 | 稀疏 / 主视觉卡 | 标题和主视觉共同占画面，主视觉可达 45%–60% |
| 2–3 个互相关联的事实 | 均衡 / 桥接卡 | 文字 50%–60%，视觉 25%–35%，用箭头、关系线或一组物件说明关系 |
| 4–6 个事实、取舍或检查项 | `notion + dense`、`bento-grid` 或 `list` | 信息块铺满主体区，图标、便签和图形嵌进单元格；不使用只有边缘装饰的大背景 |
| 3–6 个阶段或步骤 | `flow`、`linear-progression` 或 `winding-roadmap` | 让路径贯穿画面高度，步骤节点承担视觉，不留无意义中部空场 |
| 两种方案或多个维度的判断 | `comparison`、`quadrant` 或矩阵 | 以对照关系填满主体区，视觉服务差异，不额外增加装饰背景 |

文字太多时优先拆页或改成密集版式。不要把字号压到手机难读，也不要用“留白”掩盖没有设计完的下半页。

### 卡片的空间预算

- 页眉和页脚合计不超过画面高度的 12%。
- 主标题、正文信息块和主视觉合计覆盖安全画布的 78% 以上。
- 有目的的留白保持在 10%–18%，用于标题呼吸、视觉停顿或分隔层级。
- 单块连续空白超过画面 20% 时，必须由主视觉、阅读节奏或明确的下一屏暗示来解释；解释不成立就重排。
- 密集卡的视觉不单独占一块空区域，应嵌入信息块、时间线、矩阵或关系图中。

### 版式实现规则

- 内容区使用 CSS Grid 或正常文档流。除页脚外，不用绝对定位把总结框钉在底部，再留下中间空场。
- 同组卡保持色彩和字体系统一致，允许封面、密集卡、流程卡和对比卡使用不同网格。
- 背景插画要为当前页面生成或裁切。页面有四个判断时，插画应呈现四格、路径或关系；封面式留白背景只能用于封面或单个强观点。
- 信息不足时，选择一张强观点卡并放大主视觉；信息充足时，选择更多页面或更高密度网格。不得用无关装饰补信息不足。

## 合成检查

1. 主视觉是否帮助读者理解当前内容，而非只是好看。
2. 文字是否可在手机上清楚读完。
3. 事实、数据和引用是否仍能回到研究母稿。
4. 卡片去掉插画后，判断是否仍成立。若不成立，先补信息，不用图补意思。
5. 每页导出后检查三段高度。上半部、中部和下半部是否各有阅读或视觉任务；是否存在无功能的大块空区。
6. 卡片结构是否匹配当前信息单元数量。四个以上事实仍使用封面式布局时，改为密集卡、流程卡或拆页。
