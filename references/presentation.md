# 汇报与视觉交付

## 交付关系

```text
MCP 原始材料 → 单篇资料与判断 → Markdown 事实层
                                      ├─ 人类速读总结
                                      ├─ HTML / PDF
                                      └─ 手绘知识卡
```

视觉只降低阅读阻力，不能替代资料层。关键数字、日期、原话、链接和限制必须留在 Markdown 或确定性文字层中。

## 文字交付

### 赛道研究

- 以 `00_INDEX.md` 为入口。
- `sources/` 保存逐篇深读资料与原文高价值片段。
- `research/` 保存观点、案例、流程、分歧和趋势。
- 快速速查可以只交索引、单篇资料和一份赛道总结；需要长期研究或写作时再展开完整目录。

### 日报、周报与单篇拆解

- 以 `report.md` 为母稿。
- 先写事实，再写判断和边界。
- 速读内容不删除原帖入口；读者需要时能打开深读资料或原帖。

### 网页与 PDF

- 网页使用暖白背景、深灰文字、清楚的小标题和宽松行距。
- 手机优先，A4 打印不溢出。
- HTML 使用内联资源，保证单文件可打开。
- 只有用户明确需要时才生成 PDF。

## 唯一视觉风格

公开配图和分享卡统一使用 `references/visual-design.md` 定义的“手绘知识卡”。不再展示或询问多套 Baoyu 风格。

这套风格适合：

- 流程图；
- 工具或方案对比；
- 一篇文章的关键判断；
- 有出处的金句与解释；
- 赛道研究的总结图。

每次先判断哪些内容用图会明显更容易理解。装饰图、重复正文的图片和无法核实文字的图不生成。

## Baoyu 路由

可用时，按内容调用 `baoyu-article-illustrator` 或 `baoyu-infographic`，但只使用手绘知识卡这一套视觉说明。生成多张图时保持同一纸张、线条、配色、机器人和业务物件语言。

关键中文较多时，先生成构图和插画，再用 HTML、SVG 或其他确定性文字层叠加；也可以让图像模型直接生成，但必须逐字检查。发现错字、漏字、重复字或流程箭头错误时只修这一张，最多两轮。两轮仍不可靠时改用确定性文字叠加。

Baoyu 不可用时直接生成 Markdown、HTML 和基础 PNG，不要求圈友安装额外依赖。研究、来源和文字报告必须保持完整。

## 尺寸

| 用途 | 尺寸或比例 | 说明 |
| --- | --- | --- |
| 文章横图 | 16:9 | 流程、对比、总结和金句图 |
| 朋友圈卡 | 1080×1350 | 3—5 张为宜，一张只解决一个阅读问题 |
| 网页内图 | 16:9 或随正文宽度 | 手机端文字仍可读 |

## 来源与署名

- 原帖截图、作者流程图和数据图保留圈友名、帖子标题、日期与原帖链接。
- 使用作者金句时，在正文或图下注明作者和原帖；图内可以只放短署名。
- 研究者制作的流程、对比和总结图写“根据本次生财 MCP 调研整理”或用户指定署名。
- 朋友圈公开卡可以隐藏付费内容来源，但对应事实仍需保存在母稿中，不能因为公开卡不写来源就失去回查入口。

## 交付前检查

1. 每张图是否让某个关系、步骤或判断更容易理解。
2. 图内中文、数字和箭头是否与母稿一致。
3. 原图、作者原话和研究者整理是否清楚区分。
4. 手机宽度下是否能读清主要文字。
5. 图片是否按正文顺序插入，并在附近写明来源与我们的理解。
6. `scripts/check-deliverables.py` 是否通过。
