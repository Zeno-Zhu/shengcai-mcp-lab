# 汇报交付层

## 交付架构

```text
MCP 原始材料 → 分类与判断 → report.md（母稿）
                                  ├─ report.html（可读网页）
                                  ├─ card-01.png ...（朋友圈卡）
                                  ├─ visual-series/（可选视觉图文组）
                                  └─ report.pdf（明确需要时）
```

母稿是事实来源与完整分析；任何视觉版本只负责降低阅读阻力，不能替代母稿。先保留事实、取舍、推理、条件和未知项，再通过分层、分页、表格、关系图减少连接性文字。不得把完整研究压成三条泛化观点。

## 默认版式

### 网页简报

- 纸张研究简报：暖白背景、深灰文字、宽留白。
- `行动` 用深绿，`研究` 用蓝，`观察` 用琥珀。
- 手机优先，A4 打印不溢出；不依赖在线字体、图片或脚本。

### 朋友圈卡

- 尺寸：1080×1350，垂直 4:5；适合朋友圈连续图阅读。
- 公开卡与私人成果分开。公开卡不能出现对单个用户的诊断、待办和方向卡结论。
- 默认 3–5 张。卡 1 给时间、主题和这次阅读的范围；其余卡按“一篇或一个主题一张”展开；最后一张才做横向联系或阅读线索。
- 单条强信号可用 1 张，但要写清事实、判断和限制。
- 每张卡只服务一个阅读动作。超过一个主题时拆卡；卡片组用分页保存密度，禁止把多篇研究缩成一张“金句总结”。
- 不使用模型生成图片承载核心文字；用 HTML/CSS 截图确保中文、数字和数据准确。
- 出图前按当前页的信息单元选择稀疏、均衡、密集、流程或对比版式；同一张背景不得机械套用到所有页。主体区有四个以上信息块时，默认用 `dense/list/bento`，不使用封面式大留白。
- 导出后检查上半部、中部和下半部是否都有明确阅读或视觉任务。连续空白超过画面 20% 且没有构图用途时，必须重排。完整规则见 `visual-design.md`。

卡片文案用自然的第一人称分享或用户提供的口语风格。直接说清事情和判断，少用口号、泛化建议、模型腔和“不是……而是……”式翻案。标题、正文、结尾都不使用私人诊断句。

朋友圈卡只写整理后的内容和个人阅读体会，不出现圈友名、帖子标题、原帖链接、来源脚注或“作者原话”标记。完整网页、Markdown、PDF 与研究报告保留来源和案例卡，供读者回查。

## Baoyu 路由

| 用户意图 | 优先能力 | 备注 |
| --- | --- | --- |
| 阅读网页 | `baoyu-markdown-to-html` | Markdown 母稿转内联 CSS HTML；默认 `simple` 主题，用户可改。 |
| 一张视觉概览 | `baoyu-infographic` | 图像用于概览；关键数据必须留在 HTML/Markdown。 |
| 3–5 张视觉传播图 | `baoyu-xhs-images` | 遵从其两次确认流程；适合观点、故事、教程，不适合密集日报。 |
| 文本精确朋友圈卡 | HTML/CSS → PNG | 确定性渲染，不依赖图像生成。 |

视觉版卡片由 Baoyu 生成“图形、插画、纹理或结构背景”，由 HTML 叠加所有需要准确阅读的文字。这样既能保留 Baoyu 的设计能力，也能保证标题、数据、时间和引用不出错。详情见 `visual-design.md`。

若 Baoyu 子 Skill 未安装，保留 Markdown 和本地单文件 HTML/PNG 路径；不得要求用户安装整套仓库。用户明确需要某项增强能力时，再通过 Skill 安装器安装对应单项。

## 零配置与可选增强

开源 Skill 必须让没有安装 Baoyu 的圈友也能完成全部核心流程：检索、判断、Markdown、网页和文本精确朋友圈卡。首次运行时检查宿主可用 Skill；不要让用户手动寻找、复制或粘贴安装命令。

| 场景 | 未安装 Baoyu | 已安装 Baoyu |
| --- | --- | --- |
| Markdown 研究母稿 | 直接生成 | 直接生成 |
| 网页简报 | 本地单文件 HTML | 可调用 `baoyu-markdown-to-html` 增强主题 |
| 朋友圈卡 | HTML/CSS 截图 PNG | 同左，核心文字仍用确定性渲染 |
| 视觉图文组 | 说明可选增强，并询问是否安装 | 调用 `baoyu-xhs-images` 的确认流程 |
| 单张概览信息图 | 说明可选增强，并询问是否安装 | 调用 `baoyu-infographic` |

用户选择视觉图文组或信息图、且对应 Baoyu 子 Skill不可用时，明确说明它是可选增强，征得同意后由 Agent 使用 Skill 安装器从 `JimLiu/baoyu-skills` 安装**单个**需要的目录（例如 `skills/baoyu-xhs-images` 或 `skills/baoyu-infographic`）。不批量安装仓库，也不要求用户粘贴命令。安装后提示该能力将在下一轮可用；本轮可先交付基础 HTML/PNG 版本。

## 个性化署名

方向卡可保存 `微信称呼或卡片署名`。该值只用于卡片页眉或页脚，不用于搜索、MCP 提问、图片提示词或公开互动。空值保持通用版，绝不从本地账号目录或其他推测信息自动填充。

方向卡还可保存 `公开分享口吻`。取值为“平实分享”或“我的口语”。后者需要用户提供 2–3 条样本；样本只用于模仿表达方式，不能改变事实、来源和判断边界。

## 产前检查

- 母稿是否区分风向标、精华帖、日常帖等来源？
- 每一张卡是否只传达一个层级的内容？
- 数据、时间与原帖结论是否仍能回溯到母稿？
- 是否写明“信号 / 课题 / 行动”之一，而非只给热点摘要？
- 公开卡有没有把私人行动建议与公开阅读体会分开？
- 每个推荐内容是否都有事实、判断、适用边界，而非只有标题和形容词？
